# Explorer rail theme and New Tab geometry checkpoint

The Explorer tab rail now climbs its sidebar surface ladder (`surfaceSidebar`, `surfaceSidebarHover`, `surfaceSidebarSelected`) across dark and light themes instead of reusing the main pane's `surface0` / `surface1` / `surface2` tokens. The New Tab (`+`) button uses the authored 28px inline geometry when tabs fit and the 20px toolbar geometry when tabs overflow, with a 14px icon, `CHIP_RADIUS` corners, the header interaction fill, and pane-scoped open-menu highlighting (`new_tab_menu_owns_pane`). The Explorer rail also preserves the 4px `headerAction` trailing margin generated from `explorer-sidebar.tsx`.

This checkpoint does not complete desktop migration or visual acceptance. `validation.json` names the exact 297-input source archive (`344203bd5cf43ba082c59df118c333c93128b3b040f484e33a13a8c6cd5ccb90`), before/after binaries, focused tests, and remaining gaps. All 297 build inputs byte-match the checkout.

`fixture.mts`, `seed.mts`, `client.mts`, `input.py`, `dialog-input.py`, `launch.py`, and `matrix.py` drive the isolated daemon, three real Node PTYs (`main`, `pi-qa`, `grok-qa`), and X11 captures across dark and light themes. Seven states are captured per theme: `fit-idle`, `fit-tab-hover`, `fit-plus-hover`, `fit-menu`, `overflow-idle`, `overflow-plus-hover`, and `overflow-menu` (28 native before/after frames and 14 matched Electron reference frames). All eight flat surface/hover samples match Electron exactly, all three PTYs survive every native client close, and zero input bytes leak to any PTY during captures, menu interactions, or Escape dismissal.

The Electron reference producer is `reference.mts`. It uses the cached Electron export and blocks production port 6767. Its terminal uses the xterm DOM fallback renderer and does not establish hardware/WebGL rendering or overall performance acceptance. `before-rails.png`, `after-rails.png`, `reference-rails.png`, and `rail-differences.png` stack the seven dark states above the seven light states at 36px per row. Overflow rows show `x800..960` for main-header context, while quantitative comparisons in `pixel-metrics.json` evaluate the actual Explorer region (`x800..1280` when fit, `x960..1280` when overflow) with no masks. Dark fit-idle differences drop from 14,780 to 1,626 of 17,280 pixels; light fit-idle differences drop from 16,640 to 1,620 of 17,280 pixels. Visual status remains **NOT_PASSED**: window-control theme colors, menu placement/shadows, text/icon rasterization, fractional layout, selected close scrims, and scroll-boundary shades still differ.

`check-mac.sh` and `check-win.ps1` verify the frozen 297-file archive hash, build the native application on macOS (`runtime-shaders`) and Windows (stable MSVC), and run `workspace_tab_layout::tests`. Neither script launches a native GUI or modifies installed clients.

`client-close-proof.json` and `cleanup.json` record that all three isolated PTYs survived native client exit before teardown and that all private fixture processes, ports (`42583`, `44077`), Xvfb display, and temporary `PASEO_HOME` were cleaned up.
